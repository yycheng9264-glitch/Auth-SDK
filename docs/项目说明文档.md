# 项目说明文档

## 1. 项目概述

`@yycheng9264-glitch/tool-auth` 是团队内部的统一登录鉴权 SDK，解决多个业务系统各自实现登录鉴权导致的重复造轮子问题。后端提供统一的鉴权中心服务，前端通过此 SDK 标准化接入。

### 解决的问题

- **统一鉴权**：所有业务系统使用同一套鉴权流程，体验一致
- **降低接入成本**：SPA 项目一行代码 `guard().then(() => mountApp())`，HTML 页面一个 `<script>` 标签即可
- **双模式支持**：Web 应用使用 appId + appSecret 认证，企微集成使用 OAuth 授权

## 2. 功能特性

| 特性 | 说明 |
|------|------|
| Web 模式鉴权 | 用户输入 appId + appSecret，调用后端接口换取 token |
| 企微模式鉴权 | 企微 OAuth 授权，获取企业微信用户信息 |
| 鉴权守卫 | 自动检测登录状态，未登录时弹出登录页面 |
| 原生 UI 组件 | 登录弹窗/全屏页使用 Shadow DOM 实现，不依赖框架 |
| Token 管理 | localStorage 持久化，自动过期判断，60 秒缓冲 |
| 请求封装 | 可选 fetch 封装，自动注入 token、处理 401 |
| 配置集中管理 | 所有环境参数统一在 config.ts 中管理 |
| 双模分发 | npm ESM 包 + CDN UMD 包 |

## 3. 技术栈

| 技术 | 用途 |
|------|------|
| TypeScript | 开发语言，提供类型安全 |
| Rollup | 构建工具，输出 ESM / CJS / UMD 三种格式 |
| Vanilla JS | UI 层使用原生 DOM API，不依赖任何前端框架 |

## 4. 本地开发

### 环境要求

- Node.js >= 16
- npm >= 8

### 开发命令

```bash
# 安装依赖
npm install

# 开发模式（监听文件变化自动重新构建）
npm run dev

# 构建
npm run build

# 清理构建产物
npm run clean
```

### 构建产物

```
dist/
├── auth-sdk.esm.js       # ES Module 格式，供 Webpack/Vite/Rollup 等使用
├── auth-sdk.esm.js.map
├── auth-sdk.cjs.js       # CommonJS 格式，供 Node.js require 使用
├── auth-sdk.cjs.js.map
├── auth-sdk.umd.js       # UMD 格式，供浏览器 <script> 标签引入
├── auth-sdk.umd.js.map
└── types/                # TypeScript 类型声明文件
    └── index.d.ts
```

### 代码规范

- 所有导出函数、类、接口添加中文 JSDoc 注释
- 核心逻辑路径添加内联中文注释
- 文件头部用注释说明模块职责
- 命名规范：
  - 接口/类型：大驼峰，如 `AuthInfo`
  - 方法/函数：小驼峰，如 `getToken()`
  - 常量：大写蛇形，如 `STORAGE_KEY_PREFIX`

## 6. 扩展指南：添加新的鉴权模式

如果需要增加新的鉴权模式（如钉钉、飞书等），按以下步骤：

1. **在 `types/index.ts` 中**：在 `AuthMode` 类型中添加新模式名称
2. **在 `modes/` 目录下**：创建新的模式文件（如 `DingTalkMode.ts`），实现 `login(credentials)` 方法，返回 `AuthInfo`
3. **在 `config.ts` 中**：添加新模式需要的默认配置
4. **在 `AuthSDK.ts` 中**：在 `initModeHandler()` 方法中添加新模式的分支
5. **在 `LoginModal.ts` 中**：根据需要添加对应的登录表单 UI
