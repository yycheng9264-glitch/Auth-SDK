# 业务接入文档

## 1. SDK 概述

`@yycheng9264-glitch/tool-auth` 解决业务系统统一登录鉴权的问题。

**核心流程**：项目启动 → SDK 检查 token → 有 token 则继续 → 无 token 弹出登录页 → 用户输入凭据 → SDK 调后端接口鉴权 → 鉴权通过 → 执行业务逻辑。

**两种鉴权模式**：

| 模式 | 适用场景 | 用户输入 | 后端接口 |
|------|---------|---------|---------|
| **Web 模式** | 内部工具、管理后台等标准 Web 应用 | appId + appSecret | POST /auth-center/openapi/auth/token |
| **企微模式** | 集成企业微信的内部系统 | appId（输入）+ 企微授权（扫码/点击） | ① GET oauth-url ② GET login |

## 2. 快速开始

### 方式一：npm 引入（适合 React / Vue / 工程化项目）

```bash
npm install @yycheng9264-glitch/tool-auth
```

创建 SDK 实例并在入口文件调用：

```ts
// main.ts —— 应用入口文件
import { createAuthSDK } from '@yycheng9264-glitch/tool-auth'

// ============================================================
// 初始化 SDK
// ============================================================
const auth = createAuthSDK({
  mode: 'web',                              // 鉴权模式
  authCenterUrl: 'https://auth-center.example.com', // 鉴权中心地址
  loginUI: 'modal',                         // 登录 UI 样式
})

// ============================================================
// 鉴权守卫 —— 鉴权通过后才启动应用
// ============================================================
auth.guard().then(() => {
  // 鉴权通过，挂载应用
  createApp(App).mount('#app')
}).catch(() => {
  // 用户取消了登录，显示提示
  console.warn('用户取消了登录')
})
```

### 方式二：CDN 引入（适合纯 HTML 页面）

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8" />
  <title>业务系统</title>
  <style>
    /* 业务内容初始隐藏，鉴权通过后再显示 */
    #app { display: none; }
  </style>
</head>
<body>
  <!-- 业务内容 -->
  <div id="app">
    <h1>业务系统内容</h1>
  </div>

  <!-- 引入 SDK -->
  <script src="https://cdn.example.com/auth-sdk.umd.js"></script>
  <script>
    // ============================================================
    // 初始化 SDK
    // ============================================================
    const auth = AuthSDK.create({
      mode: 'wework',
      authCenterUrl: 'https://auth-center.example.com',
      loginUI: 'fullscreen',
      redirect: window.location.href,
    })

    // ============================================================
    // 鉴权守卫
    // ============================================================
    auth.guard().then(() => {
      // 鉴权通过，显示业务内容
      document.getElementById('app').style.display = 'block'
      startApp()
    })

    function startApp() {
      // 业务逻辑代码
      console.log('业务系统启动')
    }
  </script>
</body>
</html>
```

## 3. Web 模式接入

### 完整流程

```
用户打开页面 → SDK 检查 token → token 有效 → 进入业务
                              → token 无效 → 弹出登录页 → 用户输入 appId + appSecret
                                                     → 调用后端接口 → 成功 → 存入 localStorage → 进入业务
                                                                      → 失败 → 显示错误提示
```

### 配置项

```ts
const auth = createAuthSDK({
  mode: 'web',                              // 必填，鉴权模式
  authCenterUrl: 'https://auth-center.example.com', // 必填，鉴权中心地址
  loginUI: 'modal',                         // 可选，登录 UI 样式，默认 'fullscreen'
  storagePrefix: 'myapp_',                  // 可选，localStorage 前缀，默认 'auth_sdk_'
  requestTimeout: 10000,                    // 可选，请求超时(ms)，默认 15000
  tokenExpireBuffer: 120,                   // 可选，过期缓冲(秒)，默认 60
})
```

### API 参考

```ts
interface AuthSDKInstance {
  // 鉴权守卫：核心方法，未登录自动弹出登录页
  guard(): Promise<AuthInfo>

  // 检查是否已登录（仅本地判断，不调接口）
  isAuthenticated(): boolean

  // 主动触发登录
  login(): Promise<AuthInfo>

  // 登出：清除本地 token
  logout(): void

  // 获取 token
  getToken(): string | null

  // 获取用户信息（企微模式）
  getUserInfo(): UserInfo | null

  // 获取完整认证信息
  getAuthInfo(): AuthInfo | null

  // 更新配置
  updateConfig(config: Partial<AuthSDKConfig>): void

  // 带 token 的请求封装（可选）
  fetch<T>(url: string, options?: RequestInit): Promise<T>
}
```

### 使用 fetch 封装

如果选择使用 SDK 提供的请求封装，它会自动完成：

- 在请求头添加 `Authorization: Bearer <token>`
- 遇到 401 状态码自动触发重新登录
- 登录成功后重新发起原始请求

```ts
// 使用 SDK 的 fetch 封装
const data = await auth.fetch('/api/business/data', {
  method: 'POST',
  body: JSON.stringify({ key: 'value' }),
})

// 或者自己管理请求，仅从 SDK 取 token
const token = auth.getToken()
fetch('/api/business/data', {
  headers: { 'Authorization': `Bearer ${token}` }
})
```

## 4. 企微模式接入

### 完整流程

```
用户打开页面 → SDK 检查 token → token 有效 → 进入业务
                              → token 无效 → 检查 URL 有 code？
                                            ├── 有 code → 显示登录页 → 用户输入 appId
                                            │                        → 调 login 接口换用户信息
                                            │                        → 保存，清除 URL code → 进入业务
                                            │
                                            └── 无 code → 显示登录页 → 用户输入 appId，点击"企微授权登录"
                                                         → 获取 oauth-url → 跳转企微授权页
                                                         → 用户在企微授权 → 回调回到页面 ?code=xxx
                                                         → 回到"有 code"分支
```

### 配置项

```ts
const auth = createAuthSDK({
  mode: 'wework',                           // 必填，企微模式
  authCenterUrl: 'https://auth-center.example.com', // 必填
  redirect: window.location.href,           // 可选，企微回调地址，默认当前页面 origin
  loginUI: 'fullscreen',
})
```

### 关于 redirect 参数

企微 OAuth 授权完成后会回调到 `redirect` 指定的地址，并在 URL 后追加 `?code=xxx`。

**重要**：`redirect` 必须和企微应用后台配置的"授权回调域名"一致，否则企微会提示"回调地址不合法"。

推荐配置方式：如果不确定，使用 `window.location.href`，授权完成后会回跳回当前页面。

## 5. 常见问题

### Q: 初始化时需要传 appId 和 appSecret 吗？

**不需要**。`appId` 和 `appSecret` 由用户在登录页面上输入，SDK 内部使用它们去调用后端接口。初始化配置中只需要 `mode` 和 `authCenterUrl`。

### Q: 如何切换后端地址？

```ts
auth.updateConfig({
  authCenterUrl: 'https://new-auth-center.example.com',
})
```

### Q: 如何自定义登录页样式？

当前版本使用 Shadow DOM 隔离样式，不支持外部覆写。如果需要自定义样式，可以修改 `src/ui/styles.ts` 中的 CSS 变量（后续版本支持）。

### Q: 登录成功后如何获取用户信息？

```ts
// 企微模式
const userInfo = auth.getUserInfo()
console.log(userInfo?.userName, userInfo?.avatar)

// Web 模式没有用户信息，只有 token
const token = auth.getToken()
```

### Q: token 过期了会怎样？

SDK 每次初始化时检查 token 过期时间，如果已过期则自动弹出登录页重新登录。实际请求中遇到 401 也会触发重新登录。

SDK 内置 60 秒缓冲期（可通过 `tokenExpireBuffer` 配置），在 token 真正过期前 60 秒就视为无效，避免请求刚好在过期时被拒。
